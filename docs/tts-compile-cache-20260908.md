# Fish TTS 编译缓存持久化

## 目的

Fish S2-Pro 的 TorchInductor/Triton 内核原先写入容器临时目录
`/tmp/torchinductor_root`。容器重建后这些内核会被删除，首个真实请求需要再次编译，
从而出现明显的首音延迟。

## 实施

`fish_tts` 现在把 `TORCHINDUCTOR_CACHE_DIR` 指向带运行时版本和 FastAR 实现版本的目录，
并挂载命名卷 `06_fish_tts_compile_cache`。版本目录包含 Torch、CUDA、vLLM-Omni 和
FastAR 实现标识；升级这些组件时应更新目录名，避免复用不兼容的内核。

## 验证记录

- Compose 配置解析通过，缓存卷成功创建并挂载。
- 首次服务运行后缓存卷约 48 MB，确认 TorchInductor 正在写入该路径。
- 同一容器内重复固定种子请求生成相同文件：`c566000c095548719510cd43896204df75a7afa39d7449ac9aedf897f1ef7b9a`，大小 880684 字节。
- 重启后首次固定请求耗时约 13.8 秒，随后重复请求约 11.2 秒；该样本仅代表当前镜像和 GPU 状态，不能作为稳定百分比收益。
- 4 路直接 HTTP 测试全部返回 200，聚合吞吐 2.62 音频秒/墙钟秒；当前严格的连续播放模拟仍检测到约 1.99 秒最大间隙，需要单独优化流式分块节奏。

缓存只减少编译重复工作，不改变模型权重、采样参数、随机种子或并发上限。发布前应在目标 GPU 上重新测量冷启动、首音、完整 WAV 哈希和连续播放指标。
